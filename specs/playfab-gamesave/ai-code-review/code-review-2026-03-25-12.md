## Findings

### II-1 (Important): `AddCompressedFile` HRESULT silently dropped — can produce corrupted upload

**File:** `Source\PlayFabGameSave\Source\SyncManager\UploadStep.cpp`  
**Lines:** 162–165 (caller) and 213–239 (callee)

**Description:**  
In `CompressFiles`, the return value of `AddCompressedFile` is not checked:

```cpp
// Line 162-165
for (const FileDetail* fileToUpload : zipBatchSet)
{
    u.uncompressedSizeBytes += fileToUpload->fileSizeBytes;
    AddCompressedFile(localFileFolderSet, fileToUpload, saveFolder, u);  // HRESULT ignored
}
```

Inside `AddCompressedFile`, the extracted-file metadata is pushed to `u.extractedFiles` at line 229 **before** the `RETURN_IF_FAILED(JoinPathHelper(...))` at line 233 that can fail. If `JoinPathHelper` fails:

1. The file's metadata (`ExtendedManifestExtractedFileDetail`) is already recorded in `u.extractedFiles` (line 229)
2. The file is **not** added to `u.archiveContext` (line 238 never reached)
3. `AddCompressedFile` returns a failure HRESULT
4. The caller at line 165 silently discards the error
5. `u.uncompressedSizeBytes` has already been incremented (line 164)
6. `ZipFilesIntoSingleZip` at line 168 succeeds — it zips whatever files *were* added
7. The extended manifest (written from `u.extractedFiles`) lists the file as present in the zip
8. The zip does not contain the file

**Consequence:**  
On the download path, `UnzipFilesFromSingleZip` extracts only files actually present in the zip archive. The file listed in the manifest but absent from the zip is silently lost — a **phantom entry** that the manifest claims exists but was never uploaded. This is silent data loss of game save content.

**Trigger scenario:**  
`JoinPathHelper(saveFolder, relFilePath, afd.fullPath)` fails. This could occur if `GetRelFilePath` returns an empty or malformed path due to a folder-index inconsistency, or on platforms where path concatenation fails for certain character sequences.

**Suggested fix:**  
Check the return value and either propagate the error or roll back the already-pushed metadata:

```cpp
for (const FileDetail* fileToUpload : zipBatchSet)
{
    u.uncompressedSizeBytes += fileToUpload->fileSizeBytes;
    HRESULT addHr = AddCompressedFile(localFileFolderSet, fileToUpload, saveFolder, u);
    if (FAILED(addHr))
    {
        TRACE_ERROR("[GAME SAVE] UploadStep: AddCompressedFile failed for '%s', HR:0x%0.8x",
            fileToUpload->fileName.c_str(), addHr);
        // Roll back the metadata that was already pushed
        if (!u.extractedFiles.empty())
        {
            u.extractedFiles.pop_back();
        }
        u.uncompressedSizeBytes -= fileToUpload->fileSizeBytes;
        return addHr;
    }
}
```

Alternatively, move the `u.extractedFiles.push_back` in `AddCompressedFile` to **after** the `RETURN_IF_FAILED` so metadata is only recorded on success, and add `RETURN_IF_FAILED` at the call site.
